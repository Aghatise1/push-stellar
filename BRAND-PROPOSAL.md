# Push brand and design proposal

## The decision

Push should present itself as **the work record between an agreement and payment**.

The public message is:

> **Brief. Deliver. Settle.**
> One clear record from agreement to payment.

This is more specific than “a freelancing platform” and more useful than leading with blockchain. Stellar supports the settlement record; the worker, client and completed work remain the story.

## Identity

- **Name:** Push
- **Website:** `pushearn.xyz`
- **X:** `@pushearn_`
- **Primary mark:** the existing pixel-built P symbol
- **Primary descriptor:** Work with a clear record
- **Product line:** Brief. Deliver. Settle.
- **Current-stage label:** Invite-only Stellar testnet MVP

Do not use `PUSH.IO`, the purple wordmark or a second P symbol. Do not add `.IO` to the name. Do not make Stellar or USDC larger than Push.

## Visual system

| Role | Colour | Use |
| --- | --- | --- |
| Ink | `#101612` | Main text, dark backgrounds |
| Forest | `#113D31` | Brand and primary actions |
| Cream | `#F3F0E8` | Editorial background |
| Sheet | `#FBFAF6` | Product records and cards |
| Lime | `#BAF45A` | Completion and forward motion |
| Blue | `#2775CA` | Payment and network evidence |
| Vermilion | `#D95536` | Controlled structural signal |

Use Outfit or Instrument Sans where available. Headlines should be short, direct and large. Interfaces should feel like accountable work records: clear stages, dates, owners, evidence and status. Decoration must support the workflow.

## Message hierarchy

1. **Human outcome:** clear terms and proof of completed work.
2. **Product mechanism:** one connected record for the brief, delivery and payment evidence.
3. **Current proof:** a working invite-only MVP.
4. **Infrastructure:** Stellar testnet supports non-custodial settlement verification.

This order prevents Push from sounding like a token project or a generic “earn money” website.

## Rules for future assets

- Use the existing pixel P mark and the name Push.
- Use one headline, one supporting sentence and one action per asset.
- Use no more than two type sizes beyond labels.
- Keep critical X-header content within the central safe area and away from the lower-left avatar overlap.
- Show the product journey or actual interface where possible.
- Label testnet and simulated activity accurately.
- Never invent user counts, payment volume, partnerships or funding.
- Never use `PUSH.IO`, unrelated stock imagery or an oversized coin as the main idea.

## Immediate implementation order

1. Replace the X header and old purple avatar with the approved Push assets.
2. Pin one clear product explanation and pilot invitation.
3. Use the same value proposition on the home page, investor page, README and grant submissions.
4. Publish short product demonstrations showing one complete workflow at a time.
5. Review brand consistency before every public launch asset is posted.
